Contexto

O projeto

Os modelos leem a resposta do córtex visual a uma imagem (os betas de fMRI de cada exibição) e recuperam o que a pessoa viu: o embedding CLIP da imagem e, nos modelos com gerador, uma reconstrução. A comparação vale porque todos treinam nas mesmas exibições, são testados nas mesmas 1.000 imagens e passam pelas mesmas métricas.

{{cartoes_familias}}

Ao lado deles ficam os dois modelos publicados no artigo do MindEye2 (fine-tune completo, com 1 e 40 sessões), baixados e reconstruídos aqui com o mesmo pipeline, como referência.

A pergunta do plano de estágio é quanto dado cada modelo precisa. Para responder, o treino varia um fator de cada vez: o número de sessões, de imagens únicas e de repetições por imagem, o conteúdo semântico das imagens e o jeito de usar as repetições (trials separados, média dos betas, sorteio ou combinação).

Instalação

Preparar uma máquina nova

Do computador zerado ao primeiro treino, só com terminal (uma máquina acessada por SSH, sem interface gráfica). O guia completo, com os erros conhecidos, está em docs/NOVO_COMPUTADOR.md.

Precisa de
GPUNVIDIA com 20 GB (o FRR e o MindEye2 cabem em 16 GB; o MindEye1 precisa dos 20), só o driver: o CUDA vem com o PyTorch
RAM30 GB (o FRR de 40 sessões chega a ~25 GB)
Softwaregit, curl, tmux e conda (ou python3.11; o 3.12 não serve, o torch 2.1 não tem wheel)
Dadosaceitar os termos do NSD; o download usa o dataset público pscotti/mindeyev2 do HuggingFace
ParaDownloadDisco
FRR e MindEye2 com 1 sessão (bootstrap.sh --minimo)~35 GB40 GB
FRR e MindEye2 em qualquer subconjunto das 40 sessões~43 GB60 GB
Tudo: reconstrução, métricas e MindEye1 (bootstrap.sh)~130 GB200 GB

  1. Ferramentas

    sudo apt update && sudo apt install -y git curl tmux build-essential
curl -fsSLo /tmp/miniconda.sh https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash /tmp/miniconda.sh -b -p ~/miniconda3 && ~/miniconda3/bin/conda init bash && exec bash

  2. Clonar e preparar

    Dentro do tmux, para o download sobreviver a uma queda do SSH (sair sem matar: Ctrl-b e depois d; voltar: tmux attach). Interrompido, é só rodar de novo: continua de onde parou.

    tmux new -s setup
git clone {{repo}}.git && cd benchmark-modelos
setup/bootstrap.sh --check     # diagnóstico: GPU, disco e o que falta; não baixa nada
setup/bootstrap.sh             # tudo (ou --minimo, só 1 sessão)

    Só o necessário para treinar o FRR e o MindEye2 nas 40 sessões: setup/setup_env.sh --with-extras e depois ~/envs/fmri/bin/python setup/download_data.py --stage finetune --subj 1.

  3. Conferir

    ~/envs/fmri/bin/python -m unittest discover -s tests    # "OK (skipped=3)"

  4. Treinar

    Um treino é um dicionário; o treina.py faz o resto (veja Como usar).

    cd src
~/envs/fmri/bin/python treina.py --lista                 # os experimentos de src/experimentos.py
~/envs/fmri/bin/python treina.py <nome> --so_dataset    # confere o dataset sem treinar
nohup ~/envs/fmri/bin/python treina.py <nome> > ~/treino.log 2>&1 &

Os ridge-only já treinados (bootstrap.sh --ckpts) vêm do release do repositório privado mindeye2-ridge e só baixam com acesso a ele. Sem isso, os modelos se retreinam com os dicionários de src/experimentos.py.

Versionamento

Fluxo com git

O trabalho do dia a dia vai direto na main: atualizar a máquina, commitar e enviar.

git pull --rebase              # traz o que o GitHub tem a mais e põe os seus commits por cima
git add <arquivos>             # escolha o que entra (results/tables, results/site, código)
git commit -m "o que mudou"
git push
  • git status e git branch -vv dizem onde você está: "ahead 2" são dois commits seus que o GitHub não tem; "behind 1", um do GitHub que você não tem.
  • O push recusado quer dizer que o GitHub andou: rode git pull --rebase e envie de novo. O rebase muda o hash dos seus commits, não o conteúdo.
  • Uma branch e um pull request só valem a pena para uma mudança que alguém precisa revisar antes de entrar.

Este site

É o arquivo results/site/index.html, gerado por src/make_site.py. Abre direto do disco, sem servidor e sem internet (só as fontes vêm da rede). Os resultados se atualizam sozinhos: ao fim de cada treino e de cada avaliação, os scripts regeneram o site, e um modelo novo, treinado pelo treina.py, aparece com a configuração completa. O que conta como modelo novo e como tirar um modelo do site está em Como usar.

~/envs/fmri/bin/python src/make_site.py      # regenera na mão (segundos, se nada mudou)
